== Overview & Objectives

This lab focuses on diagnosing and resolving orchestration lifecycle and configuration issues in OpenShift Virtualization. By the end of this module, you will:

* Understand how OpenShift Virtualization tracks workload status conditions to validate cluster routing paths.
* Troubleshoot complex virtualization readiness blocks to ensure the system is explicitly permitted to receive application traffic.

[NOTE]
====
This lab is designed to give you hands-on experience with real-world guest integration scenarios. We highly recommend exploring the errors, running the diagnostic commands, and trying to fix the issues on your own first—that is where the best learning happens! 

If you get stuck or want to verify your findings, the companion *Guided Solution* is always available to help guide you through the next steps.
====

== Tasks

=== Task 1: Troubleshooting Workload Accessibility

==== Problem Scenario
A Virtual Machine named `vm5` is deployed in the namespace `{user}-troubleshoot-03`. Operations reports that while the virtual machine instance itself powers on and successfully reaches a running state, the environment framework completely blocks inbound application traffic from reaching the backend system services.

Run the following command to check the high-level infrastructure status of `vm5`:
[source,sh,subs="attributes+"]
----
oc get vmi vm5 -n {user}-troubleshoot-03
----

==== Reference Documentation
* link:https://redhat.com[Installing and configuring guest communication agents]

==== Goal
Investigate the virtual machine failure, perform the necessary troubleshooting steps, and bring the VM up to a completely healthy status where it can receive network traffic.

== Suggested Troubleshooting Reference Workflow

Use the following commands in sequence to analyze the operational state of the virtual machine and isolate the root cause of the connection failure:

Check high-level tracking VMI properties:
[source,sh,subs="attributes+"]
----
oc get vmi vm5 -n {user}-troubleshoot-03
----

Check execution pod deployment logs:
[source,sh,subs="attributes+"]
----
oc get pods -n {user}-troubleshoot-03
----

Describe the launcher pod configuration (replace `<pod-name>` with the active virt-launcher pod ID):
[source,sh,subs="attributes+"]
----
oc describe pod <pod-name> -n {user}-troubleshoot-03
----

Describe the live VMI object manifest data to inspect status conditions and probe logs:
[source,sh,subs="attributes+"]
----
oc describe vmi vm5 -n {user}-troubleshoot-03
----

Connect to the interactive serial console to explore the inner guest kernel runtime environment:
[source,sh,subs="attributes+"]
----
virtctl console vm5 -n {user}-troubleshoot-03
----
