== Overview & Objectives

This lab focuses on diagnosing and resolving Virtual Machine startup issues in OpenShift Virtualization. By the end of this module, you will:

* Understand the OpenShift Virtualization VM startup workflow and object lifecycle.
* Inspect key Kubernetes/OpenShift objects including VirtualMachine (VM), VirtualMachineInstance (VMI), virt-launcher pods, PersistentVolumeClaims (PVC), and DataVolumes (DV).

== Suggested Troubleshooting Workflow

When a Virtual Machine fails to start, use the following commands in sequence to isolate the root cause:

Check high-level VM states:
[source,sh]
----
oc get vm -n {user}-troubleshoot-01
----

Check high-level VMI states:
[source,sh]
----
oc get vmi -n {user}-troubleshoot-01
----

Inspect the VMI definition and system events:
[source,sh]
----
oc describe vmi <vm-name> -n {user}-troubleshoot-01
----

Locate the underlying virt-launcher pod:
[source,sh]
----
oc get pods -n {user}-troubleshoot-01 -l kubevirt.io/created-by=<vmi-uid>
----

Describe the virt-launcher pod configuration:
[source,sh]
----
oc describe pod <virt-launcher-pod> -n {user}-troubleshoot-01
----

Check storage components:
[source,sh]
----
oc get pvc,dv -n {user}-troubleshoot-01
----

Query cluster events sorted chronologically:
[source,sh]
----
oc get events -n {user}-troubleshoot-01 --sort-by='.metadata.creationTimestamp'
----

== Tasks

=== Task 1: Troubleshooting Failure Scenario A

==== Problem Scenario
A Virtual Machine named `vm1` is configured to boot from a container disk image within the namespace `{user}-troubleshoot-01`. 

When attempting to start the VM, the startup process fails and hangs indefinitely. The OpenShift Web Console reports that the system cannot spin up the workload instance.

==== Reference Documentation & Setup
* Consult the Red Hat documentation on link:https://redhat.com[Creating VMs from Container Disks].

==== Goal
Investigate the cluster components, determine why the image deployment is failing, implement a fix, and successfully transition `vm1` to a `Running` state.

=== Task 2: Troubleshooting Failure Scenario B

==== Problem Scenario
A Virtual Machine named `vm2` fails to start as expected in the namespace `{user}-troubleshoot-01`. 

The VM definition appears valid, but it fails during the early orchestration phase before rendering an operating system interface.

==== Goal
Investigate the object specifications, pinpoint the missing infrastructure dependency causing the initialization failure, fix it, and restore the VM to a fully operational state.
